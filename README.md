# 长任务 S2 多 Agent 编排执行 · 使用文档

> 版本：v1.0 ｜ 适用对象：OpenClaw / Agent 使用者 ｜ 关联技能：`s2-orchestration`

---

## 1. 项目简介

**一句话**：S2 是一套面向「长任务」的多 Agent 编排方法论，用「可靠任务书 + 结果落盘 + 查文件等待 + 分块读写 + 断点续传」五个机制，把耗时较长、需要多源调研或多文件产出的任务拆成并行子 Agent，保证**一次跑通、不卡死、不丢结果、不"图片化"中断、不重复交付**。

**它解决的问题**：当你在 Agent 环境里跑长任务（多源调研、演讲稿、可研报告、方案文档、工程清单等）时，一旦拆成多个子 Agent 并行执行，很容易踩三个坑：

1. **卡死**——主 Agent 用「数 completion event」的方式判断子任务是否完成，数错一次就死等，空转十几分钟甚至半小时。
2. **丢结果**——子 Agent 的结果只通过「完成事件文本」回传，事件被图片化/截断/丢失后，结果就没了。
3. **图片化中断**——会话上下文变大后，环境层渲染 bug 把工具输出转成图片，纯文本模型读不到，任务中断。

S2 把这三类问题的应对手段固化成一套可复用的流程和铁律。

## 2. 背景与痛点

### 痛点 A：多 Agent 等待卡死（数 completion event 死等）

**典型事故案例**：一次「融资演讲稿」任务，主 Agent 在 11:26 并行 spawn 了 3 个调研子 Agent（硫资源 / 地缘政治 / 政策）。

- 11:34:23 硫资源完成
- 11:34:29 政策完成
- 11:36:38 地缘政治完成（此时三项**已全部完成**）

但主 Agent 的计数逻辑出错：政策完成时它以为「还在等硫资源」、地缘政治完成时它又以为「其余两项仍在进行」。于是它调用 `sessions_yield` 去等一个**永远不会再来的**完成事件——因为每个子 Agent 的完成事件只会来一次，已经来过了就不会再来。

结果：11:36 → 12:03 空转 **27 分钟**，直到用户手动发「继续任务」才被唤醒。

**根因**：
- 主 Agent 依赖「数完成事件数」来判断整体是否完成。
- 完成事件**只触发一次**，把已完成的任务反复当 pending 再 yield，等于等一个不存在的事件 → 死等。
- 没有「产物文件」这个客观、可反复检查的判断依据。

### 痛点 B：工具输出「图片化」中断

**现象**：会话上下文变大后（尤其是长任务跑了很久、tool 输出很多之后），工具的输出结果不再以文本回传，而是被转成图片，上下文里显示为 `(see attached image)`。纯文本模型**读不到图片里的文字**，于是后续整合、校验全部中断。

**已确认的根因**（来自多次复盘）：
- 这是**渲染/回传层的环境级 bug / 回归**，不是配置出来的。
- **没有独立阈值配置**——不是「超过 N 字节就转图片」那么简单，而是**会话级状态触发**，甚至连 7 字节的输出都会图片化。
- 图片是**内嵌 base64**（`{type:"image", data:"<base64>"}`），随 transcript JSON 持久化，**不会落成独立 PNG 文件**，所以也没法事后从磁盘读回。

**后果**：工具输出一旦图片化，主模型（纯文本）等于「失明」，长任务在最关键的整合/生成阶段崩掉，且难以事后补救。

> 这两个痛点对应了 S2 的两个核心设计：用「查产物文件」替代「数事件」解决卡死；用「结果落盘 + 分块读 + 拆子 Agent」解决图片化。

## 3. 方法核心（S2 五要素）

### 3.1 可靠任务书（5 要素）

每个子 Agent 的任务指令（spawn 时传入）必须包含 5 要素，缺一不可：

| 要素 | 内容 | 目的 |
|------|------|------|
| **① 目标** | 一句话说清要产出什么 | 对齐预期，防止范围漂移 |
| **② 数据源** | 不用 Kimi/聚合摘要，用 `web_fetch` 抓权威源，标注置信度 | 防止数据虚构 |
| **③ 落盘** | 结果**必须**写入 `/tmp/<维度>.txt`（强制，不写视为失败） | 结果不依赖回传事件 |
| **④ 验证标准** | 结果需包含哪几项关键数据/结论 | 整合时能校验完整性 |
| **⑤ 完成信号** | 写文件后返回「已写入 <路径> + 字节数」 | 便于判断真完成 |

### 3.2 结果落盘（/tmp）

子 Agent 的产出**一律写文件**到 `/tmp/`，整合时只 `read` 文件，**绝不依赖** completion event 文本。文件是客观存在、可反复读取、可校验字节数的「硬证据」。

### 3.3 查文件等待（不数事件）

判断子任务是否完成，**只看产物文件是否齐全**，不看完成事件数。每收到一个完成事件就 `ls` 重查一遍文件清单，预期 N 个 `/tmp/*.txt` 全在且非空 → 全部完成，立即进整合。

### 3.4 分块读写

控制单次工具输出大小，避免长输出触发图片化：exec 用 `head/tail/grep` 分段、read 用 `offset/limit` 分块。

### 3.5 断点续传

每步写状态文件 `任务_<名>_state.json`，主会话重启后读状态文件、判断 phase、从断点继续，不重新拆分。

## 4. 完整流程（8 步详解）

### 步骤 1：接收 + 范围确认

- 先搞清楚三件事：**增量 vs 全量**、**交付格式**（docx/md/xlsx/pptx/pdf）、**基准文件是哪个**（多版本任务必须锁定唯一基准）。
- 写状态文件 `任务_<名>_state.json`，初始化 `phase` 和 `subtasks`。

### 步骤 2：拆分

- 调研阶段：并行 spawn N 个「维度」子 Agent（如「硫资源」「地缘政治」「政策」）。
- 撰写/整合阶段：单 Agent 串行。
- 交付阶段：单 Agent。

### 步骤 3：并行调研

按第三节的「任务书 5 要素」给每个子 Agent 下发指令，`sessions_spawn(mode="run")` 并行启动，记录每个 `childSessionKey`。每个子 Agent 结果**落盘** `/tmp/<维度>.txt`。

### 步骤 4：可靠等待

按「查文件齐全度」判断：预期 N 个文件全在且非空 → 进整合；缺哪个等哪个；超时兜底（如 15 分钟未出现 → 重查/重试/报告，不干等）；距上次报进度 > 8 分钟无实质进展 → 主动发进度。

### 步骤 5：整合

单 Agent `read` 所有产物文件，逐个校验「非空 + 含关键数据」，再汇总成完整初稿。

### 步骤 6：生成

- 文档生成用 `shutil.copy(基准文件, 目标)` 复制基准，**再替换段落文本**（保留原 pPr/rPr），严禁 `Document()` 空建 + `add_paragraph()`。
- 中文字体必须同时设置 `w:ascii / w:hAnsi / w:eastAsia` 三个属性。

### 步骤 7：验证

交付前**重新打开文件**验证：段落数、总字符数、字体/字号/缩进、zip 完整性、document.xml 可解析。

### 步骤 8：幂等交付

- 云文档：同一任务**更新同一 doc**（不每次 create 新 doc 堆版本）。
- 文件附件：MD 与 DOCX **分条发**（不要放一条消息里）。
- 邮件：**只在最终完成后发一次**（用 `send_email_once.py` 去重）。

## 5. 安装与使用

### 5.1 安装

把 `SKILL.md`（连同技能目录）放到 skills 目录下：

```text
~/.openclaw/workspace/skills/s2-orchestration/SKILL.md
```

技能会被运行时自动扫描识别。若为外部技能，可走 `clawhub` 安装流程校验。

### 5.2 触发条件（满足任一即启用）

- 任务预计 > 5 分钟，或需多源联网调研
- 需生成/重构文件（docx/xlsx/pptx/pdf/md）并交付
- 需拆分多个子任务并行执行

### 5.3 最小示例

**① 写任务书（给子 Agent 的指令）**：

```text
【目标】调研 2026 年全球硫资源供应格局，产出关键数据与结论
【数据源】不用 Kimi；用 web_fetch 抓海关总署/行业协会/路透等权威原始出处；关键数字标注来源
【落盘】结果必须写入 /tmp/research_sulfur.txt（强制，不写视为失败）
【验证标准】需包含：全球硫产量、中国进口依存度、主要产地占比、价格趋势，各至少 1 个带出处的数字
【完成信号】写文件后返回「已写入 /tmp/research_sulfur.txt + 字节数」
```

**② 并行 spawn**：

```text
用 sessions_spawn(mode="run") 并行启动 3 个子 agent：
- 硫资源  → /tmp/research_sulfur.txt
- 地缘政治 → /tmp/research_geopolitics.txt
- 政策     → /tmp/research_policy.txt
记录每个 childSessionKey
```

**③ 等待（不数事件，查文件）**：

```text
每收到一个完成事件，执行 ls -la /tmp/research_*.txt 重查：
- 3 个文件都在且非空 → 全部完成，进入整合
- 缺哪个 → sessions_yield 等哪个
- 超 15 分钟仍缺 → 重查/重试/报告，不干等
```

**④ 整合**：

```text
read /tmp/research_sulfur.txt
read /tmp/research_geopolitics.txt
read /tmp/research_policy.txt
逐个校验非空 + 含关键数据，汇总成初稿
```

## 6. 图片化应对

### 6.1 治本（配置层）

在 `openclaw.json` 启用上下文裁剪与压缩，防止上下文无限膨胀到触发图片化的会话级状态：

```jsonc
{
  "contextPruning": { "mode": "cache-ttl", "ttl": "5m" },
  "compaction": { "mode": "safeguard", "keepRecentTokens": 20000 }
}
```

再配合**主动 `/compact`** 手动压缩当前会话。

### 6.2 治标（行为层）

- **分块读**：read 用 `offset/limit`、exec 用 `head/tail/grep`，控制单次输出大小。
- **大上下文下沉子 Agent**：把重活拆到独立子 Agent 里跑，结果落盘，主会话保持轻量。
- **视觉桥**：图片/OCR/文档解析走视觉技能 `ds-vision-skill-plus`，把像素转成文字再交给主模型。

### 6.3 应急

- 已图片化且读不到 → `/new` 开新会话，**关键结论先落盘**再继续。
- 兜底：子 Agent 结果**写文件 + completion event 文本**双通道，事件丢了还有文件。

## 7. 常见坑表 + FAQ

### 常见坑表

| # | 坑 | 根因 | 修复 |
|---|---|---|---|
| 1 | 等待卡死（空转 27 分钟） | 数 completion event 死等 | 查产物文件齐全度 |
| 2 | 结果回传丢失 | 依赖 completion event 文本 | 结果强制落盘，整合只 read |
| 3 | 空文档 / 格式乱 | `Document()` 空建 + `add_paragraph()` | `shutil.copy` 基准 + 替换段落 |
| 4 | 多 agent 覆盖文件 | 未锁定基准文件 | 任务前锁定唯一基准 |
| 5 | 数据虚构 | Kimi/聚合摘要 | `web_fetch` 权威源交叉验证 |
| 6 | 邮件乱发 | 每个版本都发 | 只终版发一次 + 去重脚本 |
| 7 | 图片化中断 | 会话级环境 bug | compaction/pruning + 分块读 + 拆子 agent |
| 8 | 断点丢失 | 状态不落地 | 每步写 state.json |
| 9 | 云文档版本堆一堆 | 每迭代 create 新 doc | 同任务更新同一 doc |
| 10 | key 截断 | 复制了掩码显示 | 用完整 key，注意「…」是掩码 |

### FAQ

**Q1：为什么不能数 completion event？**
A：完成事件只触发一次，把已完成的任务反复当 pending 再 yield，等于等一个永远不再来的事件，必死等。产物文件是客观、可反复检查的依据。

**Q2：子 Agent 结果为什么必须落盘 /tmp？**
A：completion event 文本会被图片化/截断/丢失，文件是硬证据；整合时只 read 文件，不依赖回传文本。

**Q3：图片化真的没有阈值吗？**
A：已确认是渲染/回传层环境级 bug，会话级状态触发，连 7 字节输出都会图片化；没有独立阈值可调。所以只能「治本压缩 + 治标分块 + 应急 /new」。

**Q4：断点续传怎么用？**
A：主会话重启后第一件事读 `任务_<名>_state.json`，看 `phase` 字段，从对应断点继续，不重新拆分。

**Q5：邮件到底什么时候发？**
A：只在任务**最终完成**后发一次，中间 V1/V2/V3 迭代只发飞书消息；发邮件必须走 `send_email_once.py` 按文件名去重。

## 8. 配置片段（openclaw.json）

```jsonc
{
  "models": {
    // ... 已有模型配置不动 ...
  },

  "contextPruning": {
    "mode": "cache-ttl",
    "ttl": "5m"
  },

  "compaction": {
    "mode": "safeguard",
    "keepRecentTokens": 20000
  }
}
```

- `contextPruning.mode=cache-ttl` + `ttl=5m`：超出 5 分钟未被引用的历史缓存被裁剪，控制上下文规模。
- `compaction.mode=safeguard` + `keepRecentTokens=20000`：压缩时保留最近 2 万 token 的原文，避免丢关键上下文。

> ⚠️ 修改配置前先备份 `openclaw.json`；改完用 gateway 的配置热加载或重启生效。不要用一行命令覆盖整个文件，按字段 merge 进去。
